**New demonstrated defects**

1. **N1 — Major: bf16 score gathering fails during kernel expansion.**  
   [ms2_pack.rs:401](src/tensor/ops/ms2_pack.rs:401) uses `F::reinterpret(u32_word)`. CubeCL explicitly requires equal source/target sizes in [cast.rs:59](/home/user/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/cubecl-core-0.10.0/src/frontend/element/cast.rs:59).

   Concrete input: CPU bf16; `B=K=F=1`, `T=22`, `A=16`; actions `[1,108]` containing `(-1.0f32).to_bits()` at offset 106; trajectory formula slot 0; bf16 formula log-probability `−0.5`; scores `[1,2]`. Expansion rejects the 4-byte-to-2-byte reinterpretation with **“Reinterpret type sizes must match”**, instead of producing scores `[-1, -0.5]`. Packed/resident packing calls this producer at [generate.rs:2798](src/models/ms2/generate.rs:2798).

   **Minimal fix:** decode the word with `f32::reinterpret`, then convert, or gather into f32 scores. Add a bf16 producer-through-ranking test: the current regression directly uploads scores at [ms2_pack_kernels.rs:1278](tests/ms2_pack_kernels.rs:1278).

2. **N2 — Minor: both workspace readout adapters silently omit enabled evidence.**  
   [generate.rs:2340](src/models/ms2/generate.rs:2340) and [generate.rs:2381](src/models/ms2/generate.rs:2381) call the base readout. That readout initializes evidence to zero at [generate.rs:1693](src/models/ms2/generate.rs:1693) and never gathers the evidence buffers.

   Concrete scenario: use the f32 iodine/carbon evidence fixture at [ms2_packed.rs:818](tests/ms2_packed.rs:818), generate with Table/TraceOnly and `evidence=true`, then read the warmed bucket through either adapter. Full generation has nonzero evidence, explicitly required at test line 927; adapter output instead has zero evidence count/status/details.

   **Minimal fix:** reject `evidence=true` in both adapters until they route through the complete evidence readout.

3. **N3 — Minor: packed validation accepts exhausted enumeration as complete.**  
   [pack.rs:861](src/models/ms2/pack.rs:861) checks completeness only through `scored == joined`. The shared counter validator at [contract.rs:906](src/models/ms2/contract.rs:906) checks saturation/exhaustion without checking completeness.

   Concrete input: start with a valid filled enumeration packed record; retain valid provenance and `joined=scored=1`, then set `visited=u32::MAX−1`, add `FORMULA_SEARCH_EXHAUSTED`, and leave `formula_support_complete=1`. Validation accepts this false whole-window completeness claim. The specification explicitly requires saturated enumeration to clear completeness at [MS2_CONTRACTS.md:639](docs/MS2_CONTRACTS.md:639).

   **Minimal fix:** validate completeness together with search status, rejecting `complete=1` for exhausted enumeration—including saturated counters. Apply the rule consistently to packed and unpacked validation.
